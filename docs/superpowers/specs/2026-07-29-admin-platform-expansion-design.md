# 管理后台完整内容与站点配置管理设计

## 目标

将仅供本机使用的 `admin` 后台扩展为博客内容、站点展示配置和本地资源的统一管理入口。日常修改不再需要直接编辑 Markdown、数据文件或 `src/config.ts`；结构复杂且不适合表单化的配置保留高级 JSON 编辑入口。

## 范围

### 内容

- 文章：保留现有 Markdown 编辑，并补齐首页精选、首页分区、文章状态、运行环境和最后验证日期字段。
- 项目：管理 `src/data/projects.ts` 的全部字段，包括状态、精选、技术栈、标签、日期、链接与封面。
- 相册：管理 `public/images/albums/<id>/info.json`、本地照片和封面；支持新建相册、上传图片、排序与隐藏。
- 技能：管理 `src/data/skills.ts`，包括等级、经验、关联项目、图标及颜色。
- 时间线：管理 `src/data/timeline.ts`，包括时间、类型、组织、技能、成就、链接、图标及精选状态。

### 站点

- 站点与个人资料：站点标题、副标题、描述、域名、语言、个人资料、社交链接。
- 首页与导航：四个首页分区的标题/简介/图标、精选文章数量、导航栏项目、公告。
- 展示与功能：主题色、页脚、评论、音乐、功能页开关、侧边栏组件配置。
- 高级设置：以受保护的 JSON 表单编辑其余可序列化设置；保存前显示变更预览并校验 JSON。

### 资源与发布

- 资源库：浏览、上传、删除文章图片、项目图片与相册图片；每项显示引用位置与可复制路径。
- 分类与标签：保留现有词库，并让文章、项目、相册可复用。
- 发布：显示当前工作区改动、构建状态和部署钩子结果；仍只在配置了部署钩子时触发远程部署。

## 信息架构与交互

侧边栏分为“内容”“站点”“资源与发布”三组。每个实体页采用一致的三栏或两栏工作区：左侧筛选和集合切换、中部列表搜索与新增、右侧表单编辑。移动端收叠为纵向布局。

所有表单共享以下行为：必填与格式校验、保存前摘要、成功/失败提示、未保存离开警告、删除二次确认、图片拖放/上传预览。状态、精选和隐藏采用统一的彩色徽章与开关控件，颜色仅表达状态而非承载唯一信息。

## 数据与接口设计

后台服务继续使用本地 Node HTTP 服务，所有写入都限定在仓库根目录下的已声明路径。

- 数据集合 API 扩展为 `projects`、`skills`、`timeline`；各集合提供列表、读取、新建、更新和删除。
- 相册 API 提供相册元数据、图片上传、封面替换、排序与删除；外链相册只编辑 `info.json`，不下载外链图片。
- 文章 API 扩展前置元数据序列化，支持 `featured`、`contentSection`、`status`、`testedOn`、`lastVerified`。
- 设置 API 将 `src/config.ts` 的可表单化导出映射到白名单字段；高级 JSON 接口只允许白名单导出，保存前生成 `.backup`。
- 资源 API 对文件名做规范化，拒绝路径穿越和仓库外目标；上传类型限制为图片扩展名。
- 发布 API 只读取 Git 状态和运行既有构建/部署流程，不执行任意 shell 命令。

## 兼容性与迁移

现有数据文件仍维持 TypeScript 导出结构，后台读写时仅替换指定数组或配置对象，避免改写工具函数和类型定义。现有项目中 `liveDemo`、`sourceCode`、`visitUrl` 三种链接字段会完整保留并在表单中明确命名。相册维持当前按目录扫描的前台逻辑。

## 错误处理与安全

后台仅支持 `127.0.0.1` 本机访问，沿用密码会话。每个写入接口验证请求体、字段枚举、日期和 URL；失败时不写文件并返回可读错误。写入前创建备份，写入使用临时文件后原子替换。删除资源前检查引用并提示潜在影响。

## 测试与验收

- 后端单元测试覆盖：集合读写往返、字段校验、路径限制、相册元数据和文章状态/精选字段。
- 前端源级测试覆盖：导航分组、各管理页表单字段、保存/删除确认和高级 JSON 入口。
- 集成验证：以临时目录运行 API，执行文章、项目、相册、技能、时间线与设置的新增、修改、删除流程。
- 最终运行后台测试、既有 Vitest 测试与 `pnpm build`；构建不得因新后台功能失败。

## 分期

1. 建立通用数据集合与表单框架，补齐文章状态/首页字段和项目完整字段。
2. 接入技能、时间线、相册及资源管理。
3. 接入站点设置、高级 JSON 和发布工作台，并统一完成可用性与安全校验。
